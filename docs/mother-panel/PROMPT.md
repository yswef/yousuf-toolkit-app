# برومت موجّه إلى موديل لوحة التحكم الأم (Mother Panel)

> انسخ الكتلة التالية كما هي إلى الموديل المشغّل للوحة الأم. لا تعدّل خارج لوحة الأم.
> ملاحظة تصحيحية: موقع `yousef.romoozbasmah.com` مبني بـ **PHP** وليس WordPress.

```text
أنت الموديل المسؤول عن «لوحة التحكم الأم» (Mother Panel) لمجموعة تطبيقات المطوّر يوسف الحمزي.
مهمتك الآن تحسين البرومت التأسيسي للوحة الأم وتطوير ميزة «لوحات التحكم» لتناسب تطبيقنا الحالي
Y- Dimensions (تطبيق موبايل فقط، المطوّر يوسف الحمزي، yswefalhmzy@gmail.com).

أولاً: صحّح الفهم السابق
- القاعدة «لا جداول جديدة» كانت فهماً خاطئاً. المقصود الأصلي: الجداول الموجودة (users والجداول
  المعروفة) جاهزة ويجب ألا تتكرر ولا يُنشأ جدول مستخدمين لكل تطبيق. إضافة جداول جديدة غير مكررة
  مسموحة ومطلوبة: devices (أجهزة المستخدم)، content_packs (حزم التحديثات الفرعية)،
  app_requirements (متطلبات التطبيقات)، asset_sources (مصادر الأصول)، releases (الإصدارات).
- قاعدة البيانات واحدة موحّدة، كل استعلام مقيّد بـ app_id، ولا يوجد جدول users لكل تطبيق،
  ويسمح بنفس البريد في أكثر من تطبيق بحساب منفصل لكل تطبيق.
- الموقع مبني بـ PHP وليس WordPress. أي تشخيص سابق بـ WordPress يُحذف من التوثيق والواجهة.
- مبدأ «أوفلاين أولاً» ملغى: المطوّر يملك استضافة Hostinger وجاهز للعمل أونلاين؛
  تسجيل الدخول إلزامي قبل تشغيل التطبيق، والمزامنة بين الأجهزة مطلوبة.

ثانياً: اجعل لوحة كل تطبيق API فعلياً للتحكم بالتطبيق بكل شيء
- لا تكتفِ بعرض إعلاني. لوحة كل تطبيق يجب أن تكون قابلة للاستدعاء كـ API حقيقي:
  قراءة وكتابة بيانات التطبيق، المستخدمين، التراخيص، الإعدادات، المحتوى، الإعلانات،
  الإحصائيات، الأجهزة المسجّلة، وحزم التحديثات، مع توحيد كل نقطة تحت لوحة الأم وحدها
  (لوحة الأم وحدها تملك الكود والتوكن؛ اللوحات التابعة لا تملك كوداً مستقلاً).
- عرّف لكل تطبيق عقداً (contract) باسماء النقاط والمدخلات والمخرجات، وسجّله في لوحة الأم،
  واجعل الاستدعاءات تُسجّل في audit_log و sync_log برقم طلب فريد لمنع التكرار.
- أضف إدارة الإصدارات من لوحة الأم: إنشاء إصدار، رفع ملف APK/حزمة بيانات، تفعيل/إيقاف إصدار،
  تحديد الإصدار الأدنى المطلوب، ونشر «تحديث فرعي» (بيانات فقط بلا APK) يُسحب عند بدء تشغيل التطبيق.

ثالثاً: التنقل بين لوحة الأم ولوحة التطبيق
- عند النقر على بطاقة تطبيق في لوحة الأم تفتح «لوحة التحكم الخاصة بالتطبيق» داخل نفس الموقع،
  بكل مميزاتها (تبويباتها، جداولها، أوامرها، إعداداتها)، لا مجرد بطاقة معلومات.
- أضف زراً عائماً ثابتاً في كل لوحة تطبيق نصّه «العودة للوحة التحكم الأم» يعيد إلى لوحة الأم،
  ويحافظ على حالة الجلسة والتبويب الذي كان مفتوحاً.
- أضف نفس الزر العائم في كل موقع وصفحة ولوحة تحكم ووثيقة: يرجع إلى «الموقع الأساسي».
  إن كانت الصفحة أو لوحة التحكم مقفلة/محمية بكلمة مرور، فالزر يرجع إلى «لوحة التحكم الأساسية»
  (وليس إلى صفحة عامة)، ولا يكشف أي بيانات قبل المصادقة.
- لا تُنهَفذ هذه الأزرار بروابط ثابتة مفصّلة؛ استخدم مساراً مركزياً واحداً يُعرّف في إعدادات الموقع.

رابعاً: برومت الموديل الذي يجهّز لوحة تحكم تطبيق
- عدّل البرومت الأساسي الذي يُعطى للموديل الذي يبني لوحة تحكم أي تطبيق، وألزمه بأن يكتب
  ملفاً باسم MOTHER_PANEL_HANDOFF.md داخل مجلد توثيق التطبيق، موجّهاً إليك أنت
  (موديل لوحة الأم)، يشرح بالتفصيل: التعديلات التي تحتاجها لوحة الأم لتشغيل هذا التطبيق
  ولوحة تحكمه، نقاط API المطلوبة، الجداول الجديدة غير المكررة، الصلاحيات، المتطلبات الخاصة،
  وخطوات التحقق. اقرأ هذا الملف عند تثبيت أي لوحة تطبيق وطبّق ما فيه قبل إعلان الاكتمال.
- لا تعتبر تثبيت أي تطبيق مكتملاً إلا بعد قراءة ملف MOTHER_PANEL_HANDOFF.md الخاص به،
  تنفيذ بنوده، وتسجيل نتيجة التنفيذ في سجل التثبيت.

خامساً: تبويب «متطلبات التطبيقات» (مطلوب صراحةً)
أضف تبويباً بهذا الاسم في لوحة التحكم الأم بقسمين:
  1) «مصادر الأشياء»: قسم مستقل لكل نوع أصل — الصوتيات، الصور، الأيقونات، الخطوط،
     الفيديو، الملفات والبيانات — يعرض المصدر، الرابط/المسار، الترخيص، والحالة.
  2) «متطلبات التطبيقات»: لكل تطبيق قائمة بكل ما يحتاجه من صور وصوتيات وبيانات ومعلومات
     وأصول وأذونات وخدمات، مع ذكر المصدر لكل بند، وعلامة «تم توفيره / ناقص»،
     ودرجة الأولوية، وملاحظة تشرح المطلوب بالضبط.
- اطلب هذه المتطلبات صراحةً في البرومت الذي يوجّه موديل لوحة التطبيق، وسجّلها في الموقع
  مع الفرز (حسب التطبيق، ثم الأولوية، ثم الحالة: الناقص أولاً) حتى يعرف المطوّر
  exactly ما ينقص كل تطبيق ليكتمل، ويستطيع التأشير على البند عند إحضاره.
- اربط البند بمصدره في القسم الأول، وأظهر عدّاداً: عدد النواقص لكل تطبيق، وإجمالي النواقص.

سادساً: التحقق قبل إعلان الاكتمال
- تحقق من ترتيب التثبيت وبصمات الملفات، وأن الجداول الموحّدة لم تتكرر، وأن كل استعلام مقيّد بـ app_id،
  وأن نقاط API تعيد JSON لا HTML، وأن الأزرار العائمة موجودة في كل صفحة بما فيها المقفلة،
  وأن ملف MOTHER_PANEL_HANDOFF.md لكل تطبيق مقروء ومنفّذ. ثم اكتب تقرير تحقق موقّت.

لا تخترع قيماً حسّاسة (كلمات مرور، توكنات، عناوين قواعد بيانات)؛ اطلبها من المطوّر عند اللزوم.
لا تغيّر اسم التطبيق Y- Dimensions ولا نوعه (موبايل) ولا بيانات المطوّر.
```
